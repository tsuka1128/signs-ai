# 仕様書：AI分析の質向上 — 直近月シグナルの併用（案B）＋ null表現の修正

> ステータス：設計・仕様（実装前）
> 対象：`src/app/api/ai/analyze/route.ts`
> 目的：体温の「安定した基調（3ヶ月平均）」と「直近の動き（最新月）」を両立させ、AI分析・提案の質を高める。あわせて体温データ欠損時の `null` 表現を修正する。

## 背景・課題

PR#176 で体温を **等加重の3ヶ月トレーリング平均**にした（小サンプルのノイズ安定化が目的）。これは正しいが、**直近の急変が平均で薄まる**という弱点がある。

一方、平均を「最新重視の加重平均」に変えると、最新月の比重が上がり、**3人部署では再び単月ノイズに振られる**（トレーリング平均を入れた意味が半減）。

→ 加重はせず、**平均（安定指標）はそのまま／直近の動きを別データとしてAIに渡す**ことで両立させる（案B）。

## 確定方針（案B）

1. **基調指標は等加重3ヶ月平均のまま**（`avg_pulse` を変更しない）。
2. **直近の動きを別途AIに渡す**：トレーリング窓内の**月次推移**を per-dept・全社で渡す。
3. **プロンプトで役割を明示**：平均＝安定した基調、月次推移＝直近の動き（最新月ほど“今”だが、回答数が少ない月は鵜呑みにしない）。乖離・トレンドの向きに注目させる。
4. **データ欠損の `null` 表現を修正**（後述）。

## 実装詳細（`src/app/api/ai/analyze/route.ts`）

### A. 月次推移データの追加
- per-dept および全社（summarizeMonth 相当）に、トレーリング窓（当月＋過去2ヶ月）の**各月の単月pulseと回答数**を古い順で付与する。
  ```ts
  monthly_pulse_trend: [
    { month: "2026-04", pulse: 3.8, respondents: 3 },
    { month: "2026-05", pulse: 3.5, respondents: 4 },
    { month: "2026-06", pulse: 2.9, respondents: 3 },
  ]
  ```
  - `pulse` は**その月単月**の平均（トレーリングではない）。回答ゼロの月は `pulse: null`、`respondents: 0`。
  - `avg_pulse`（3ヶ月平均・等加重）は**従来どおり headline として保持**。
- 設問別スコア（`question_scores`）は現状の3ヶ月集約のままでよい（推移は overall pulse のみでバランスを取る。プロンプト肥大化を避ける）。

### B. プロンプトでの役割明示
- 既存の「体温は3ヶ月移動平均」の説明（`route.ts:420` 付近）に追記：
  - `avg_pulse`（3ヶ月平均）＝**安定した基調指標**。誤検知を避けるための土台。
  - `monthly_pulse_trend`＝**直近の動き（速報）**。最新月ほど現在の状態を表すが、**回答数（respondents）が少ない月は個人の主観に振れるため鵜呑みにしない**。
  - 着眼点：**3ヶ月平均と直近月の乖離**（例：平均は横ばいだが直近月で急落＝要注視）、および**推移の向き**（上昇/下降トレンド）を捉え、急変の兆しを早期に指摘する。

### C. `null`（データ欠損）表現の修正（先のレビュー指摘①）
- 現状、部署別投入行（`route.ts:530` 付近）が `体温:${d.avg_pulse}` で、`avg_pulse` が null のとき**文字列 "null" が出力**され、AIが「体温0＝最悪」と誤読し得る。
  - → null のときは **`体温:データなし`** と出す。
  - `monthly_pulse_trend` の各月の `pulse: null` も、テキスト化する場合は「データなし」と明示（JSONで渡す場合は `null` のままでよいが、整形テキストにするなら明示）。
- `historicalContext` は `JSON.stringify` なので `null` のままで可（AIはJSON nullを「データなし」と解釈できる）。投入“テキスト行”側だけ要修正。

## スコープ
| 項目 | 対象 |
|---|---|
| `monthly_pulse_trend`（月次単月pulse＋回答数）を per-dept・全社に追加 | ✅ |
| プロンプトに「平均=基調／直近=速報・小サンプル注意」の役割明示 | ✅ |
| `体温:null` → `体温:データなし` の表現修正 | ✅ |

## 留意・レビュー観点
- 単月pulseは「その月の survey_answers のみ」で算出（トレーリングと混同しない）。1レスポンス内の question_id 重複排除は既存方針を踏襲。
- 回答ゼロ月は `pulse: null` / `respondents: 0`（0点と区別する）。
- `system_settings` のプロンプトを変更する場合は CLAUDE.md に従い PR説明に変更内容を記載。動的に組み立てる `prompt`（データと一緒に渡る側）に役割説明を入れること（カスタムプロンプトの会社にも届くように）。
- DB変更・migration 不要。
