# 仕様書：組織マトリックスのリデザイン（プロダクト計画：イーロン）

> ステータス：設計・仕様（実装前）
> 対象：`src/components/dashboard/sections/MatrixSection.tsx`、`src/components/dashboard/ScatterPlot.tsx`、`src/app/page.tsx`（matrix セクション）、`src/app/api/ai/analyze/route.ts`（AI解説の追加）
> 目的：SignsAIの核（成果に「体温」を重ねて組織の今を見る）が、初見ユーザーにも一目で伝わり感動する「組織マップ」に作り直す。

## 診断（なぜ伝わらないか）
現状は1枚に視覚変数を盛り込みすぎ：X=人数 / **Y=合成式「一人当たり生産性＝KPI達成率×(体温/3.0)」** / サイズ=達成率 or 人件費 / 色=体温 / 波紋=KPI100% / 背景=4象限。
- 最大の問題は **Y軸が合成式**で、式を読まないと意味不明。体温が「色」と「Yの中」に二重に入り発散。
- 部署/第2軸トグルが分かりにくい。読み方がホバー/docsリンク頼み。

## 新コンセプト：「組織マップ」＝ 規模 × 成果 × 体温
| 視覚変数 | 割り当て | 意図 |
|---|---|---|
| **X軸** | 人数（規模） | どれだけの人員か |
| **Y軸（既定）** | **KPI達成率（%）** ※合成式は廃止し実数に | どれだけ成果が出ているか |
| **色** | 体温（緑=良好/黄=要注意/赤=危険/灰=未取得） | その組織は健康か |
| **サイズ** | 人件費（あれば）／無ければ均一 | 投資規模（任意・控えめ） |

読み方（4象限、説明不要）：
| | 少人数 | 多人数 |
|---|---|---|
| **高達成** | 精鋭・高効率 | 主力エンジン |
| **低達成** | 育成中・立ち上げ | 要テコ入れ |

色（体温）が重なることで「多人数×低達成×赤＝疲弊して危険」「同×緑＝立ち上げ期で前向き」と**打ち手まで一目**＝SignsAIの価値が伝わる瞬間。

### Y軸トグル（一人当たり生産性も残す）
- 既定は **KPI達成率（実数・直感的）**。
- セグメント切替で **「一人当たり生産性（KPI×体温/3.0）」** にも変更可（組織づくりの重要視点として残す）。
- 切替時はY軸ラベルと象限の意味づけも連動。合成指標を選んだ時のみ、軸の小さな注記で式を表示。

## レイアウト：2つのマトリックスを縦に（トグル廃止）
- **上：部署マトリックス（主役）** — 大きく。
- **下：{第2軸名}マトリックス** — 第2軸が設定されている場合のみ表示。
- 部署/第2軸のトグルは廃止（縦並びで両方一目）。
- タイムラプス（現在/1m/3m/6m/1年）は**ページ上部に1つ**置き、両マトリックスに共通適用（状態が分かるよう「●現在/○過去」を明確に）。

## 各マトリックスのAI解説（必須）
各マトリックスに**AIの読み解き**を併置（「数字の羅列」で終わらせない）：
1. **自動読み取り見出し（決定論・クライアント計算）**：データから「どの部署/軸がどの象限か・要注目はどれか」を1行で（例：「主力のCMO室が"要テコ入れ"象限・体温も低下傾向」）。AI未実行でも必ず出る。
2. **AI解説テキスト**：`analyze` の出力に **per-view の短い読み解き**を追加する（`matrix_insight: { dept: string; axis: string }`、各2〜3文）。プロンプトで「人数×KPI達成率×体温の図から、注目すべき部署/軸と打ち手を述べる（個人名なし）」と指示。未生成時は自動読み取り見出しのみ。

## 初見ユーザーへのガイダンス
- 図の上に**1行の結論**（上記の自動読み取り見出し）。
- **インラインの「読み方」**（X=人数／Y=成果／色=体温／4象限の意味）を凡例とセットで常時表示（docsリンク頼みをやめる）。
- ホバーで各部署/軸の詳細（人数・KPI達成率・体温・主要KPI内訳）。

## デザイン（美しく・落ち着いた配色）
- 直近の方針（PR#190/#194）と統一：**チカチカさせない**。象限背景は極薄（彩度低）、グリッドは細い。色は体温の4状態のみ意味を持たせ、他は中立スレート。
- 余白・タイポgrヒエラルキーを整える。カードは白＋細枠＋`shadow-sm`。
- バブルのホバー/選択でフォーカス（他を淡く）させ、視線誘導。
- 波紋アニメ（KPI100%）は控えめ or 廃止（視覚過多回避、要判断）。

## データ（既存利用）
- `displayDepts` / `displayAxes` に **人数(head/headHistory)・KPI達成率(kpiAch/History)・体温(pulse)・人件費(totalLaborCost)・生産性(productivity)** がすでに揃っている（新規DB照会不要）。
- Y軸=KPI達成率は `kpiAch`、一人当たり生産性は `productivity` をそのまま使う。

## レビュー観点（Claude）
- 既定Y軸がKPI達成率の実数（合成式でない）で、軸/象限ラベルと整合。
- 体温が「色」だけに集約され二重計上していないか。
- 部署/第2軸が縦2枚で、第2軸未設定時は出ないか。
- 各マトリックスのAI解説/自動見出しが、該当ビューのデータに正しく対応（部署↔dept、第2軸↔axis）。
- 配色がチカチカしない（彩度低・象限極薄）。
- タイムラプスが両マトリックスに正しく適用され、過去月表示が明確。
- 既存データ（kpiAch/productivity/pulse/labor）の取り違えがないか。
- 匿名性（部署/軸単位の集計なので個人特定なし）・小規模での誤読配慮。
