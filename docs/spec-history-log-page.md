# 仕様書：履歴ログページ `/history`（通知ログ＋AI分析履歴）

> ステータス：設計・仕様（実装前）
> 目的：既読にすると消えてしまう通知や、過去のAI分析を後から遡れる「溜まっていくログ」ページを新規実装する。
> 方針確定：**通知ログとAI分析履歴は混ぜず、タブで分けて表示**する。

## 背景・課題（コードで確認済み）
- 通知ベルは **未読のみ**表示（`/api/notifications` GET が `is_read=false` 限定）。**既読にすると消えて二度と見られない**。
- 通知の過去ログを見るページが**存在しない**（`src/app` に history/log系なし）。`/history` リンクは受け皿の予定だったが未実装で404だった。
- AI分析は `ai_insights` に**月次で蓄積**されている（`onConflict: company_id, target_month, insight_type`）が、過去月を遡る画面が無い（ダッシュボードは最新のみ）。

## 全体方針
- 新規ルート **`/history`** を実装。**2タブ**構成：
  1. **通知ログ**（既読含む全通知の時系列一覧）
  2. **AI分析履歴**（過去月のレポート閲覧）
- 通知の**クリック先**（該当レポート/部署へ飛ぶ）は別件の修正（PR#184）でOK。`/history` は**アーカイブ閲覧**用で役割が異なる。両立させる。

---

## タブ1：通知ログ
- ユーザー宛の**全通知（既読・未読とも）**を `created_at` 降順で一覧表示。
- 各行：タイトル / 本文 / 日時 / 既読バッジ / type アイコン。クリックで `notification.link` へ遷移（遷移時に既読化）。
- 件数は直近 50〜100 件程度＋「もっと見る」or ページング（最小実装は limit 100 でも可）。
- **データ取得**：現状 `/api/notifications` GET は未読限定。**全件取得の手段を用意する**：
  - 案：`/api/notifications?all=1&limit=100` のように、`all` 指定時は `is_read` フィルタを外す（ベルの既定は未読限定のまま）。
  - RLS（`migration 076` ＋ super_admin対応 PR#182）が会社・ロール・部署でスコープするので、取得は安全。
- アクセス：ログイン済みの全ロール（自分宛が見えるだけ）。

## タブ2：AI分析履歴
- `ai_insights` から**過去月のレポート**を新しい順に一覧 → 選択でその月の `deep_report`（executive_summary / correlation / strategic_alignment / risks / recommendations）を表示。
- `ai_insights` は `company_id, target_month, insight_type` で月次蓄積済み。`target_month` 降順で月リストを作り、月ごとに内容を出す。
- 表示は既存の `ReportSection` / `DeepReport` コンポーネントを**再利用**できると良い（同じ見た目で過去月を出す）。
- アクセス：**全社のレポートは経営機密**のため、`admin / executive / super_admin` のみ（既存ダッシュボードのレポート表示権限と揃える）。manager に出す場合は自部署の insights_by_dept に限定するなど別途検討（本フェーズは経営層向けに限定でよい）。

---

## 導線（エントリーポイント）
- **通知ベルのドロップダウン下部に「通知をすべて見る」リンク**を追加 → `/history`（通知タブ）。現状ベルには「すべて既読」しかなく、全件への導線が無い（`Header.tsx:160`付近）。
- 必要ならサイドメニュー/ヘルプ配下にも `/history` への入口を追加（任意）。

## スコープ
| 項目 | 対象 |
|---|---|
| `/history` ページ新規（2タブ：通知ログ / AI分析履歴） | ✅ |
| 通知の全件取得手段（`?all=1` 等で既読含む） | ✅ |
| ベルに「通知をすべて見る」導線追加 | ✅ |
| AI分析履歴は過去 `ai_insights` を月次で閲覧（既存DeepReport再利用） | ✅ |
| 通知のクリック先（レポート/部署へ） | ❌ 別件PR#184で対応済み・本仕様では変更しない |
| 通知・分析の自動削除/保持期間 | ❌ 今回は無制限蓄積でよい（将来検討） |
| DB変更・migration | ❌ 不要（既存 notifications / ai_insights を読むだけ） |

## レビュー観点（Claude）
- 通知全件取得が RLS でユーザーにスコープされているか（他人・他社の通知が漏れない）。ベルの既定（未読限定）を壊していないか。
- AI分析履歴タブのアクセス制御（admin/executive/super_admin）。manager/player に経営レポートが漏れないか。
- 2タブが**明確に分離**されているか（通知とレポートを混在させない）。
- 既読化の挙動（履歴で開いたら既読にするか／一覧表示だけで既読にしないか）の一貫性。
- `ai_insights` の `target_month` 突合（YYYY-MM / YYYY-MM-01 形式の正規化）。
- super_admin が通知タブで会社の通知を見られるか（PR#182 のRLSと整合）。
