# 仕様書：設問カテゴリの可視化 — 部署レーダー（案A）＋ AIカテゴリ所見（案D）

> ステータス：設計・仕様（実装前）
> 対象：`src/app/dept/page.tsx`（案A）、`src/app/api/ai/analyze/route.ts` ＋ ダッシュボード表示（案D）
> 目的：ボイスチェックの設問カテゴリ（engagement / speed / friction …）を活用し、部署の「体温プロフィール」を可視化＋AI所見に昇格する

## 背景
PR#176 で `survey_questions.category` を AI分析に渡すようにした。このカテゴリを画面でも活かす。

## カテゴリ → 3テーマの束ね（確定）
標準11問のカテゴリを3テーマに集約する。**各テーマのスコア = 配下カテゴリの平均**。

| テーマ | 配下カテゴリ |
|---|---|
| **推進力** | speed / friction / clarity / readiness |
| **関係性** | safety / feedback / transparency |
| **意欲** | engagement / challenge / impact / workload |

- カスタム設問（`category` が標準外/null）は**3テーマのレーダーには含めない**（テーマに属さないため）。粒度の細かい値は既存の「今月の設問別スコア」リストでカバーされる。
- 注：`friction` は「調整・根回しが少ないほど良い」など**逆転項目の可能性**がある。回答時点でスコアが「高い=良い」に正規化されているか実装時に確認し、テーマ平均で符号が混ざらないようにする（現状 survey は5段階で「高い=良い」想定。要確認）。

## 案A：部署の体温プロフィール レーダー @ `/dept`

### 配置
- `/dept` ページ、「今月の設問別スコア」セクションの近く（上または下）に新規セクション「体温プロフィール」を追加。
- 既存の per-question リストは詳細用として残す（レーダー＝3テーマの輪郭、リスト＝設問別の粒度、で役割分担・重複なし）。

### 表示（recharts `RadarChart`）
- 軸：**3テーマ（推進力 / 関係性 / 意欲）**、スケール 0〜5。
- ポリゴン2枚を重ねる：
  1. **当該部署**（実線・teal）
  2. **会社平均**（破線・グレー） ← レーダーの価値は比較にあるので必須。
- 凡例で「自部署 / 全社平均」を区別。

### データ（重要）
- **3ヶ月トレーリング平均**で算出（当月＋過去2ヶ月）。3人部署でも形が安定するように（PR#176 と同じ思想）。
- 当該部署のテーマ別スコア：トレーリング窓の survey_answers を question→category→theme で集約し、テーマごとに平均。
- 会社平均：**全社**の survey_responses+answers をトレーリング窓で取得し、同様にテーマ別平均。
  - `/dept` は現状この部署の回答しか取得していないため、**会社全体のテーマ別平均を出す追加クエリ or 集計が必要**。
- `survey_questions` のクエリに **`category` を追加**（現状 `src/app/dept/page.tsx:284` は `id, text, sort_order` のみ取得）。

### 匿名ガード（確定）
- 当該部署の**トレーリング窓の回答者数が3名未満**ならレーダーを表示しない（既存 `passesAnonymityGuard` / `ANONYMITY_THRESHOLD=3` と統一）。プレースホルダー（「回答者が少ないため非表示」）を出す。
- 会社平均側も、全社の回答が3名未満なら平均線を出さない。

### 代替案（実装時に選択可・任意）
- 3軸レーダーは三角形で視覚的にやや薄い。物足りなければ **11スポークを3テーマで色分け** したレーダーに切替も容易（軸=11カテゴリ、テーマごとに色帯）。まずは3テーマ版でMVP。

## 案D：AIレポートにカテゴリ所見を昇格 @ ダッシュボード

### 方針（軽量）
AI分析は既に設問カテゴリ別スコア（`question_scores`）と `low_score_items` を受け取っている（PR#176）。出力の `deep_report.correlation` は既にダッシュボードに表示されている。これを活かす。

### 実装
1. **プロンプト強化**（`analyze/route.ts`）：`deep_report.correlation` の指示に「**特にスコアの低いカテゴリ（テーマ）を名指しし、それが当月のどのKPIに効いている可能性があるか**を具体的に述べる」を追加。出力スキーマは変えず、既存 `correlation` テキストの質を上げる。
2. **表示**：`correlation` は既にダッシュボードのレポートに表示されているはずなので、原則**表示改修は不要**。表示箇所を確認し、カテゴリ名が出るようになっているか目視確認する。
   - もし構造化して見せたければ（任意・フェーズ2）、出力スキーマに `category_findings: [{ theme, level: "low|mid|high", finding }]` を足してカード表示する。本フェーズではテキスト強化に留める。

## レビュー観点（Claude）
- テーマ集約のカテゴリ割当（推進力/関係性/意欲）が正しいか、逆転項目（friction等）で符号が混ざらないか
- トレーリング窓（当月＋過去2ヶ月）の月跨ぎが正しいか
- 会社平均が全社の回答から正しく算出され、当該部署のみに偏っていないか
- 匿名ガード（3名未満非表示）が部署・全社平均の両方に効いているか
- `category` をクエリで取得しているか（select漏れ防止）
- カスタム設問がテーマ平均に誤って混入していないか
- 案D：`correlation` にカテゴリ名が実際に出るか、ダッシュボード表示が壊れていないか
