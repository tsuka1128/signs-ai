# 仕様書：設問カテゴリの可視化 — 部署レーダー（案A）＋ AIカテゴリ所見（案D）

> ステータス：設計・仕様（実装前）
> 対象：`src/app/dept/page.tsx`（案A）、`src/app/api/ai/analyze/route.ts` ＋ ダッシュボード表示（案D）
> 目的：ボイスチェックの設問カテゴリ（engagement / speed / friction …）を活用し、部署の「体温プロフィール」を可視化＋AI所見に昇格する

## 背景
PR#176 で `survey_questions.category` を AI分析に渡すようにした。このカテゴリを画面でも活かす。

## カテゴリ → 3テーマの束ね（確定）
標準11問のカテゴリを**5テーマ**に集約する。**各テーマのスコア = 配下カテゴリの平均**。5軸（五角形）はレーダーとして読みやすい。

### 束ね方の原則（重要）
「似ているカテゴリ」ではなく、**「低いと分かったとき、誰がどんな手を打てるか（テコ入れ＝レバー）が1テーマ＝1レバーになる」** ように束ねる。原因の異なる問題を同じテーマに混ぜない（打ち手が分岐するため）。

| テーマ | 配下カテゴリ | 低いときのテコ入れ（レバー） | 主な担い手 |
|---|---|---|---|
| **意思決定・実行** | speed / friction | 権限委譲、承認フロー・会議の簡素化 | 経営（仕組み） |
| **方向づけ** | clarity / readiness / transparency | 目標と優先順位の明確化、情報共有の徹底 | マネージャー |
| **関係性・安全** | safety / feedback | 1on1、フィードバック/賞賛文化、安全性の醸成 | HR×マネージャー |
| **意欲・成長** | engagement / challenge / impact | 挑戦機会の付与、キャリア設計、仕事の意味づけ | HR×経営 |
| **働きやすさ** | workload | 増員、業務再配分、労務・残業管理 | HR/経営 |

（2+3+2+3+1 = 標準11カテゴリすべてをカバー）

- **workload を単独テーマ「働きやすさ」にしている**のは意図的。impact（意義）と混ぜると「働きがいが低い」が“忙しすぎ”か“意味を感じない”か判別できず打ち手が分岐するため。負荷を独立させることで、低スコア＝即リソース判断につながる。
- テーマ名は「負荷」ではなく**「働きやすさ」**にする。設問（workload=「業務量は質を維持できる範囲でしたか？」）は **5＝良い** なので、「負荷」だと高い＝悪いと誤読される。「働きやすさ」なら全5軸とも「高い＝良い」で統一され直感的。
- 1設問のみのため振れやすいが、3ヶ月トレーリング平均（既定）で緩和する。
- 前提：**全設問が「5＝良い」に統一済み**（friction の逆転設問は別PRで肯定形に言い換え）。テーマ平均で符号が混ざらない。

### カスタム設問の扱い（方針A・確定）
- **カスタム設問（`category` が標準外/null）はレーダーに含めない。**
- 理由：レーダーは「全社共通のものさしで 自部署 vs 全社平均」を見るもの。カスタム設問は会社独自で他社・全社比較の土俵に乗らない。
- カスタム設問は**既存の「今月の設問別スコア」リストに表示済み**なので情報は失われない。
- （将来、カスタム設問もレーダーに溶かしたい場合は、SurveyTab作成時にテーマを割り当てる拡張＝方針C。`survey_questions.category` 列を流用。本フェーズ対象外。）

### 逆転項目の注意（解消済み）
- かつて `friction`（調整・根回し）の設問が否定形で「5=取られすぎ（悪い）」と解釈され得る逆転項目だったが、**別PR（friction設問の肯定形言い換え）で「5=良い」に統一済み**。本番DBも標準11問すべて category ありを確認済み。
- 実装時：万一カスタム設問等で「少ないほど良い」項目が将来追加されても、テーマ平均で符号が混ざらないよう前提（全問5=良い）を維持すること。

## 案A：部署の体温プロフィール レーダー @ `/dept`

### 配置
- `/dept` ページ、「今月の設問別スコア」セクションの近く（上または下）に新規セクション「体温プロフィール」を追加。
- 既存の per-question リストは詳細用として残す（レーダー＝5テーマの輪郭、リスト＝設問別の粒度、で役割分担・重複なし）。

### 表示（recharts `RadarChart`）
- 軸：**5テーマ（意思決定・実行 / 方向づけ / 関係性・安全 / 意欲・成長 / 働きやすさ）**、スケール 0〜5。
- ポリゴン2枚を重ねる：
  1. **当該部署**（実線・teal）
  2. **会社平均**（破線・グレー） ← レーダーの価値は比較にあるので必須。
- 凡例で「自部署 / 全社平均」を区別。

### データ（重要）
- **3ヶ月トレーリング平均**で算出（当月＋過去2ヶ月）。3人部署でも形が安定するように（PR#176 と同じ思想）。
- 当該部署のテーマ別スコア：トレーリング窓の survey_answers を question→category→theme で集約し、テーマごとに平均。
- 会社平均：**全社**の survey_responses+answers をトレーリング窓で取得し、同様にテーマ別平均。
  - `/dept` は現状この部署の回答しか取得していないため、**会社全体のテーマ別平均を出す追加クエリ or 集計が必要**。
- `survey_questions` のクエリに **`category` を追加**（現状 `src/app/dept/page.tsx:284` は `id, text, sort_order` のみ取得）。

### 匿名ガード（確定）
- 当該部署の**トレーリング窓の回答者数が3名未満**ならレーダーを表示しない（既存 `passesAnonymityGuard` / `ANONYMITY_THRESHOLD=3` と統一）。プレースホルダー（「回答者が少ないため非表示」）を出す。
- 会社平均側も、全社の回答が3名未満なら平均線を出さない。

### 代替案（実装時に選択可・任意）
- さらに詳細にしたければ **11スポーク（カテゴリ別）を5テーマで色分け** したレーダーに拡張も容易。まずは5テーマ版でMVP。

## 案D：AIレポートにカテゴリ所見を昇格 @ ダッシュボード

### 方針（軽量）
AI分析は既に設問カテゴリ別スコア（`question_scores`）と `low_score_items` を受け取っている（PR#176）。出力の `deep_report.correlation` は既にダッシュボードに表示されている。これを活かす。

### 実装
1. **プロンプト強化**（`analyze/route.ts`）：`deep_report.correlation` の指示に「**特にスコアの低いカテゴリ（テーマ）を名指しし、それが当月のどのKPIに効いている可能性があるか**を具体的に述べる」を追加。出力スキーマは変えず、既存 `correlation` テキストの質を上げる。
2. **表示**：`correlation` は既にダッシュボードのレポートに表示されているはずなので、原則**表示改修は不要**。表示箇所を確認し、カテゴリ名が出るようになっているか目視確認する。
   - もし構造化して見せたければ（任意・フェーズ2）、出力スキーマに `category_findings: [{ theme, level: "low|mid|high", finding }]` を足してカード表示する。本フェーズではテキスト強化に留める。

## レビュー観点（Claude）
- テーマ集約のカテゴリ割当（推進力/関係性/意欲）が正しいか、逆転項目（friction等）で符号が混ざらないか
