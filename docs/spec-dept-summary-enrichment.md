# 仕様書：ボイスチェックの声（部署AI要約）の強化

> ステータス：**改訂（セクション別の入力分離＋配色の見直し）**
> 対象：`src/app/api/ai/dept-summary/route.ts`（AI生成）、`src/app/dept/page.tsx`（表示）、`dept_ai_summaries`（カラム追加）、`src/types/database.ts`
> 目的：「ボイスチェックの声（AI要約）」を、声を届けるパートと分析パートに役割分担し、目に優しい配色にする。

## ⚠️ 改訂：セクションごとに入力データと役割を分ける（最新・最重要）

PR#189 で全セクションに定量データを渡したが、**「ポジティブな声」「課題・改善要望」にまで数値分析が混ざってしまった**（例：「AI活用スコアが1.33」「全社平均を0.42下回る」等が課題欄に出る）。これを改める。

### セクション別の役割（確定）
| セクション | 入力 | 出力の性質 |
|---|---|---|
| **ポジティブな声** | **自由コメントのみ**（定量は渡さない/使わない） | 実際の声を**箇条書き**で。AIの解釈・分析・数値は最小限。生の声を届ける |
| **課題・改善要望** | **自由コメントのみ** | 同上（前向きでない声・要望を箇条書き） |
| **深掘り分析（背景と示唆）** | 自由コメント＋**定量**（設問別/低スコア/体温/全社比/前月比） | 声と数字を統合した分析（PR#189の方針を維持） |
| **マネージャーへの注目点** | 自由コメント＋**定量** | 具体的アクションヒント（同上） |

### ポジ/課題の作り方（重要）
- **自由コメントだけ**を根拠に、**実際に寄せられた声を箇条書き**（各声1行）で抽出する。「こんな声が届いています」と分かる形。
- **個人を特定しない**（固有名詞・特定業務は一般化）が、**できるだけ生の言い回しを残す**（過度に要約・抽象化しない）。
- スコア・全社比・前月比などの**数値は本文に持ち込まない**。
- 該当する声が無い場合のみ「目立った声はありませんでした」程度（潜在リスクの示唆は深掘り分析側で行う）。
- 出力形式：箇条書き（各行 `・…`）。UIは行ごとにリスト表示。

### プロンプト構造の指示
- 自由コメントは全セクションに渡す。定量コンテキストも渡すが、**「定量データは deep_dive と manager_hint の分析にのみ使う。positive_summary / negative_summary には数値を持ち込まず、自由コメントの声をそのまま箇条書きにする」と明示**する。

## 配色の見直し（目に優しく）
現状、ポジ=teal・課題=rose・深掘り=indigo・注目点=amber と**鮮やかな色背景が4色**入り乱れて「チカチカ」する。

- **濃い/鮮やかな全面背景をやめ、白〜極薄背景＋細い左ボーダー（または小アイコン）で種別を示す**トーンに統一。
- 彩度を落とした落ち着いた配色に（例：本文は `text-slate-700`、種別アクセントは細い左罫や小さな見出し色のみ）。
- `manager_hint` の blur グロー装飾（`bg-amber-500/5` のぼかし円）は削除して情報密度を上げすぎない。
- セマンティクスは残してよい（ポジ＝控えめなteal系、課題＝控えめなrose系）が、**面で塗らず**アクセントは最小限に。

---

## DB・型・UI（PR#189から継続）
- migration：`dept_ai_summaries` に `deep_dive text`（追加済み）。
- 型：`database.ts` の Row に `deep_dive: string | null`（追加済み）。
- UI：
  - ポジ/課題を**箇条書きリスト表示**（`positive_summary`/`negative_summary` を改行分割して `<li>`、空行は除外）。
  - 深掘り分析・注目点はそのまま（`whitespace-pre-wrap`）。
  - 旧キャッシュ（`deep_dive` 空/null）は深掘りセクション非表示。

## maxTokens
- 2000 を維持（深掘り分析が長文のため）。

## レビュー観点（Claude）
- **ポジ/課題に数値が混ざっていないか**（自由コメント由来の声だけになっているか）。
- ポジ/課題が**箇条書きの実際の声**になっているか（過度な抽象要約・AI解釈になっていないか）。
- 匿名性（個人名・特定業務を出さない・3名ガード維持）。
- 深掘り/注目点は定量込みの分析を維持しているか。
- 配色がチカチカせず落ち着いているか（4色面塗りの解消）。
- 旧キャッシュ・声が少ない場合の表示が壊れないか。
