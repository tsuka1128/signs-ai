# 仕様書：「今月の設問別スコア」に全社平均との比較を追加

> ステータス：設計・仕様（実装前）
> 対象：`src/app/dept/page.tsx`（部署マネジメントの「今月の設問別スコア」セクション）
> 目的：各設問の自部署スコアを**全社平均と並べて比較**できるようにする（添付イメージのような「自部署バー＋平均バー」のペア表示）。

## 背景
- 現状の「今月の設問別スコア」は、自部署の設問別スコアを単一バーで低スコア順に表示しているだけ。
- 「平均と比較したい」（自部署が全社平均より高いか低いか、設問ごとに一目で見たい）。

## 確定方針
- 各設問の行に、**自部署スコア**と**全社平均スコア**の2本を並べて表示（添付のペアバー）。
- 比較対象は **全社平均**（全部署横断）。月は**自部署の表示月（`currentYM = latestDataYM`）と同月**で揃える（フェアな「今月」比較）。
- 既存の低スコア順ソートは維持（課題の深い設問が上）。

## 実装詳細（`src/app/dept/page.tsx`）

### データ
- 既存：`qScores`（設問別・自部署・`currentYM`）。`QuestionScore` を **`companyAvg: number | null` 追加**で拡張。
- **全社平均（同月・設問別）の算出**：PR#177 で既に取得済みの `companyResponses` / `companyAnswers`（`companyAnswerByResponse`）を利用。
  - `companyResponses` を `currentYM`（自部署の表示月）で絞り、設問IDごとにスコア平均を計算 → `companyAvgByQuestion[questionId]`。
  - 1レスポンス内の `question_id` 重複排除は既存方針を踏襲。
  - 注意：`qScores` の算出は現状 company データ取得より前にある（コード順）。company平均を出すため、**qScores の確定を company データ構築後に移す**か、後段で `companyAvg` をマージする。
- 各 `qScores[i]` に `companyAvg`（同月・全社のその設問平均、無ければ null）を持たせる。

### 匿名性・小サンプルガード
- セクション全体は既存どおり自部署の `passesAnonymityGuard`（3名以上）で表示制御。
- **全社平均バーは、全社の当月回答者数が3名未満なら出さない**（`company3mResponsesCount` ではなく当月の全社回答者数で判定。なければ company 当月レスポンス数でガード）。null のときは「全社 —」表示。

### UI（添付イメージ準拠）
- 各設問の行に2本のバー：
  1. **自部署**：実線・スコア色（現状の `isLow/isMid/isHigh` の配色を流用）。数値併記（例 `2.00 / 5.00`）。
  2. **全社平均**：細めのグレーのバー（添付の「チーム平均」グレー）。数値併記（例 `全社 3.10`）。
- 0〜5スケールで横並び。スコア色は自部署側のみ（平均は常にグレーで中立）。
- 低スコア順ソートは自部署スコア基準で維持。
- 任意：自部署が全社平均を下回る設問に控えめな印（「全社比 −1.1」等）を付けると、テコ入れ箇所が際立つ（あれば良い・必須ではない）。

## レビュー観点（Claude）
- 全社平均が `currentYM`（自部署と同月）で、トレーリングと混ざっていないか。
- 1レスポンス内 question_id 重複排除が自部署・全社とも一致しているか。
- 全社平均が「全部署横断」で、自部署のみに偏っていないか（companyResponses が company 全体か）。
- 小サンプル時に全社平均バー/数値が誤って 0 や生値で出ないか（null→「—」）。
- qScores 確定タイミングの移動で既存表示（低スコア順・匿名ガード）を壊していないか。
- super_admin 代理時、全社平均が対象会社にスコープされているか（companyId 明示）。
