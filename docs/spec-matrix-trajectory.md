# 仕様書：組織マトリックス v2 — 軌跡・ラベル・なめらかアニメ

> ステータス：設計・仕様（実装前）
> 対象：`src/components/dashboard/ScatterPlot.tsx`、`src/components/dashboard/sections/MatrixSection.tsx`、`src/app/page.tsx`（マトリックスデータ）
> 目的：マトリックスを「静止画」から「動く地図」にする。各部署/第2軸が**どの領域にいて・過去からどう動き・何を意味するか**を一目で伝え、ページの価値を最大化する。

## 役割分担（確定的 vs AI）
| 要素 | 出どころ |
|---|---|
| どの領域にいるか | **確定的**（座標から） |
| 過去→現在の動き（軌跡・方向） | **確定的**（履歴データ headHistory / kpiAchHistory / productivityHistory から） |
| その意味・打ち手 | **AI**（`matrix_insight`・実装済み） |
→ 新規AIや新規DBは不要。既存の履歴配列を使う。

## ① バブルの部署名ラベル（常時表示・衝突回避）
- 各バブルの近傍に**部署名/第2軸名を常時表示**（ホバー不要で「どれがどれか」分かる）。
- **衝突回避**：ラベルが重なる場合は位置をずらす（dodge）／近接時は引き出し線・小さめ表示などで重なりを避ける。多数でも破綻しないこと。
- ラベルは控えめなトーン（slate系・小さめ）。バブル色（体温）と競合させない。

## ② 軌跡（トラジェクトリ）＋ 矢印 — チェックボックスで表示切替
- 各バブルに、**直近数ヶ月（例：3〜6ヶ月）の (x=人数, y=Y指標) の推移を結ぶ薄い軌跡線＋現在地への矢印**を描画。
  - 「どこから来て今ここ」が見える（例：SEED→開拓者へ上昇＝改善）。
  - Y指標は `yAxisMode`（KPI達成率 / 一人当たり生産性）に連動。
  - 座標計算は本体バブルと同じスケール（maxH/maxY）を使い、ズレないこと。
- **表示/非表示はチェックボックス**「軌跡を表示」で切替（既定：**ON**）。矢印が邪魔なときはOFFにできる。
- 軌跡は**薄い色・細線**でチカチカさせない。多部署でも視認性を保つ（淡色・必要なら選択バブルのみ濃く）。

## ③ 移動方向の意味づけ（確定的）
- 各バブルに**移動方向バッジ**（↑改善 / ↓悪化 / →横ばい）。基準は「現在 vs 軌跡始点（または前月）」のY指標差分（しきい値で3分類）。
- 表示場所：ホバーのリッチツールチップ内（＋ラベル脇に小アイコンでも可）。
- 「なぜ・打ち手」は既存の `matrix_insight`（AI解説）が担当。

## ④ タイムラプス切替を「ふわっと」（なめらかアニメ）
- タイムラプス（現在/1m/3m/6m/1年）切替時、バブルの**位置遷移を滑らかに**。
- 現状 `transition-all duration-300` → **700〜1000ms・ease-out**（ふわっと流れる）に。
- 位置（cx/cy）とサイズの両方にイージングを適用。過度に遅くしない（操作の手応えは残す）。

## データ（page.tsx）
- 軌跡のため、各バブルデータに**履歴配列**（`headHistory` / `kpiAchHistory` / `productivityHistory` / `pulseHistory`）を含めて ScatterPlot に渡す（既に `displayDepts`/`displayAxes` に存在）。
- ScatterPlot 側で、タイムラプス基準月（targetIdx）から過去Nヶ月分の (x,y) を算出して軌跡を描く。
- 新規DB照会なし。

## スコープ
| 項目 | 対象 |
|---|---|
| バブル常時ラベル（衝突回避） | ✅ |
| 軌跡＋矢印・チェックボックスでON/OFF（既定ON） | ✅ |
| 移動方向バッジ（確定的） | ✅ |
| タイムラプスのなめらかアニメ（700〜1000ms ease-out） | ✅ |
| AI解説（matrix_insight） | 既存・変更なし |
| データ取得・DB | 既存履歴を利用・新規なし |

## レビュー観点（Claude）
- ラベルの衝突回避が効き、多部署でも重ならず読めるか。
- 軌跡の座標が本体バブルと同一スケール（maxH/maxY）で、yAxisMode に連動しているか（達成率/生産性でズレない）。
- 軌跡チェックボックスのON/OFF・既定ON。OFF時に矢印/線が完全に消えるか。
- 移動方向バッジの基準（始点 or 前月）が一貫し、しきい値が妥当か。
- アニメが「ふわっと」（700〜1000ms ease-out）・速すぎ/遅すぎないか。位置とサイズ両方。
- 配色がチカチカしない（軌跡は淡色・細線）。
- 部署/第2軸の2マトリックスとも同様に機能するか。

## ⑤ 追加：部署/第2軸の表示フィルタ（凡例兼フィルタ）＋ レイアウト

### レイアウト（グラフを狭めない）
- マトリックスカード内を**横2カラム**に：
  - **左：グラフ（左寄せ）** — 現状の幅を狭めない（現在は左右に余白がある）。
  - **右：凡例兼フィルタパネル** — 余っている右スペースに配置。
- レスポンシブ：画面が狭いときは右パネルをグラフの下に回す（縦積み）。

### 凡例兼フィルタ
- 各部署/第2軸ごとに1行：**[✓チェックボックス] ＋ 体温の色ドット ＋ 名前 ＋ 移動方向（↑改善/↓悪化/→横ばい、任意）**。
- これにより「**どの色がどの部署か**（凡例）」と「**表示/非表示**（フィルタ）」を同時に提供。
- チェックを外すと、その**バブル・常時ラベル・軌跡**をマトリックスから非表示にする。
- 既定：**全てON**。「全選択 / 全解除」のショートカットを用意。
- 部署マトリックスは**部署リスト**、第2軸マトリックスは**軸リスト**（それぞれ独立した表示状態）。

### 実装メモ
- `MatrixSection` で表示中ID集合（部署用／軸用で別々の state）を保持し、`ScatterPlot` に渡すデータを**フィルタ済み配列**にする（非表示はそもそも描画されない＝ラベル密集も解消）。
- 自動 dodge（top/bottom）は軽い密集用に併存。重い密集はフィルタで手動整理。

### レビュー観点（追加）
- 左寄せグラフが狭くなっていない（余白活用）か。狭い画面で右パネルが下に回るか。
- チェックOFFでバブル/ラベル/軌跡が完全に消えるか。全選択/全解除が効くか。
- 部署/軸でフィルタ状態が独立しているか。色ドットが体温色と一致しているか。

## ⑥ 追加：全コントロールをマトリックス毎に集約＋レイアウトの空白解消

### コントロールの集約（マトリックス毎・自己完結）
- **上部の共通コントロールカードは廃止**。各マトリックス（部署／第2軸）の操作パネル（右側）に、そのマトリックス専用のコントロールを集約する：
  - **タイムラプス**（現在/1m/3m/6m/1年）
  - **軌跡を表示**チェック
  - **Y軸モード**（KPI達成率 / 一人当たり生産性）
  - **凡例兼フィルタ**（[✓]＋色ドット＋名前＋移動方向、全選択/全解除）
- **状態はマトリックス毎に独立**：部署と第2軸で、タイムラプス月・軌跡ON/OFF・Y軸モード・フィルタを**それぞれ別々に**操作できる（例：部署は当月、第2軸は3ヶ月前、を同時に見られる）。
  - state を `dept*` / `axis*` で分ける（month, showTrajectory, yAxisMode, excludedIds）。
  - これに伴い、各 `ScatterPlot` は自分の月・モードで描画する（バブル位置も履歴 `targetIdx` から算出し、その月に追従）。
  - 自動見出し・AI解説の対象も各マトリックスの状態に整合させる。

### レイアウトの空白解消（不格好なギャップを無くす）
- 現状 `justify-between` ＋ グラフ固定560px ＋ パネル `flex-1 max-w-[240px]` の組合せで、**中央に死んだ空白**ができている。
- 修正：**`justify-between` を廃止**し、**グラフを `flex-1`（余白を埋めて伸びる）**、パネルを固定幅（例 `w-[280px] shrink-0`）にして**隣接配置**（`gap-6`）。
  - グラフは狭めない（むしろ広い画面で伸びる）。パネルはすぐ右に寄り添い、間延びした空白を作らない。
- 狭い画面（lg未満）は従来どおり縦積み（パネルがグラフ下）。

### レビュー観点（追加）
- 上部共通コントロールカードが無くなり、各マトリックスのパネルに全コントロールが入っているか。
- 部署/第2軸で **タイムラプス・軌跡・Y軸モード・フィルタが完全に独立**して動くか（一方の操作が他方に影響しない）。
- バブル位置が各マトリックスのタイムラプス月に追従するか（履歴 targetIdx 基準）。
- グラフとパネルの間に死んだ空白が無いか（グラフが flex-1 で伸び、パネルが隣接）。狭画面で縦積みになるか。
